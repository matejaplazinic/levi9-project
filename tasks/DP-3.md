# Spec: DP-3 Data lake bucket (CDK) — V1

Status: implemented

## Objective

Add the first piece of infrastructure to the project repo, described as code: an S3 bucket that will
hold our own data (Novi Sad, station 35120) in a bronze/silver/gold layout. The same code must always
create the same infrastructure and remove it cleanly.

Done when:
1. `cdk deploy` and then `cdk destroy` both succeed with no manual steps (no console clicks, no
   emptying the bucket by hand).
2. `pytest` and `ruff` run and pass.
3. `CLAUDE.md` describes the project, the commands and the rules.

## Decisions (confirmed)

| Topic | Decision |
|---|---|
| CDK CLI | Installed globally: `npm install -g aws-cdk`. The repo has no Node files. |
| CDK language | Python, `aws-cdk-lib` v2 + `constructs`. |
| Encryption | SSE-S3 (`BucketEncryption.S3_MANAGED`), plus `enforce_ssl=True` (HTTP requests denied). |
| Public access | `BlockPublicAccess.BLOCK_ALL`, `ObjectOwnership.BUCKET_OWNER_ENFORCED` (ACLs off). |
| bronze/silver/gold | Convention only: prefix constants in code, documented in CLAUDE.md, covered by tests. No placeholder objects. |
| Destroy | `RemovalPolicy.DESTROY` + `auto_delete_objects=True`. CDK adds a small Lambda that empties the bucket before deletion. |
| Bucket name | Generated by CloudFormation (globally unique, no collisions). Exposed as a stack output `DataBucketName`. |
| Stack | `DataLakeStack`, account from the `mateja` profile, region `eu-north-1`. |

## Tech Stack

- Python 3.14 (`py`), existing `.venv`
- `aws-cdk-lib` 2.x, `constructs` 10.x (runtime of the CDK app)
- AWS CDK CLI (global npm), Node 26
- `pytest` (+ `aws_cdk.assertions` for template tests), `ruff` (lint + format check)

## Commands

```bash
py -m pip install -r requirements.txt -r requirements-dev.txt   # in the .venv
ruff check .
ruff format --check .
pytest
cdk synth --profile mateja
cdk diff --profile mateja
cdk deploy --profile mateja
cdk destroy --profile mateja --force
```

`cdk.json` sets `"app": ".venv\Scripts\python.exe app.py"` so the CDK CLI uses the project venv
(backslashes because the CLI runs the app through `cmd`).

## Code Style

Same as DP-2, enforced by ruff (line length 120, rules `E`, `F`, `I`, `B`, `UP`):

```python
DATA_PREFIXES = ("bronze/", "silver/", "gold/")


class DataLakeStack(Stack):
    def __init__(self, scope: Construct, construct_id: str, **kwargs) -> None:
        super().__init__(scope, construct_id, **kwargs)
        self.bucket = s3.Bucket(
            self,
            "DataBucket",
            encryption=s3.BucketEncryption.S3_MANAGED,
            block_public_access=s3.BlockPublicAccess.BLOCK_ALL,
            object_ownership=s3.ObjectOwnership.BUCKET_OWNER_ENFORCED,
            enforce_ssl=True,
            removal_policy=RemovalPolicy.DESTROY,
            auto_delete_objects=True,
        )
```

## Testing Strategy

- TDD: write the template assertion first, then the stack code.
- `tests/infra/test_data_lake_stack.py` synthesizes the stack and checks with `Template.from_stack`:
  - exactly one data bucket, with SSE-S3 (`AES256`) encryption;
  - all four public access block flags set to `true`;
  - a bucket policy that denies requests where `aws:SecureTransport` is `false`;
  - `DeletionPolicy: Delete` and the auto-delete custom resource present;
  - the output `DataBucketName`;
  - `DATA_PREFIXES == ("bronze/", "silver/", "gold/")`.
- The existing 63 DP-2 tests keep passing.
- Live check (manual, once): `cdk deploy` → check the bucket in the console (encryption, Block Public
  Access, policy) → `cdk destroy` → confirm the bucket and stack are gone.

## Boundaries

- **Always:** use profile `mateja`, region `eu-north-1`; run `ruff` and `pytest` before each commit;
  commit messages and PR titles in English, prefixed with `DP-3:`; work on `feature/DP-3-infra`, PR into
  `develop`; run `cdk diff` before `cdk deploy`.
- **Ask first:** `cdk deploy` and `cdk destroy` (they create and delete real AWS resources); adding
  dependencies beyond those listed here; pushing and opening the PR.
- **Never:** write secrets, tokens or the account ID into code or `cdk.json`; touch
  `levi9-praksa-2026-data`, `TouristApiStack` or the `CDKToolkit` bootstrap stack; run
  `cdk bootstrap`; commit `cdk.out/`.
